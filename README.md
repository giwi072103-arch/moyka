# BUKHARA WASH

Telegram Mini App для автомойки: React + Vite, Node.js + Express, PostgreSQL. Русский интерфейс, суммы в UZS, отображение дат в Asia/Tashkent. Мобильная версия, светлая и тёмная темы.

## Проверка проекта

API покрыт интеграционными тестами, frontend собирается. Перед запуском для клиентов необходима проверка реального входа Telegram, ролей и работы с вашим PostgreSQL. Начальные цены и контактные данные нужно настроить в админке.

## Возможности

- Каталог услуг с категориями, ценами и длительностью. Начальные цены — примеры; владелец должен их проверить.
- Вход по подписанным Telegram initData, серверные роли: клиент, мойщик, администратор.
- Гараж: марка, номер Узбекистана (физлица и юрлица), фото JPEG/PNG/WebP до 2 МБ.
- Заказ в живую очередь с комментариями и ценой, зафиксированной на момент оформления. Это **не запись на конкретное время**.
- Клиент не может оформить второй активный заказ на ту же машину.
- Мойщик подаёт заявку с ФИО и телефоном; владелец одобряет её в админке. Права не выдаются автоматически.
- Выход на смену, приём заказа, статусы «принят / мойка / готов / завершён».
- Переписка внутри заказа, обновление каждые 4 секунды; список заказов обновляется каждые 10 секунд. Это чат в приложении, не SMS.
- Отзывы после завершения, реквизиты для добровольных чаевых (опционально, AES-256-GCM).
- Управление услугами, едиными ценами, сотрудниками, пользователями, оплатой и контактами.
- Сводка заказов, подтверждённых оплат и оценок; журнал административных действий.
- Оплата на месте. Администратор вручную отмечает получение денег. **Платёжный шлюз и автоматическое подтверждение P2P не подключены.**

## Быстрый локальный запуск

Нужны Node.js 22+ и PostgreSQL 16+ (локально можно через Docker).

```bash
npm ci
cp .env.example .env
docker compose up -d db
npm run build
node --env-file=.env server/index.js
```

Для локальной собранной версии поставьте `APP_URL=http://localhost:3000` в `.env`. Для разработки frontend запустите в двух терминалах `npm run dev:api` и `npm run dev`, оставив `APP_URL=http://localhost:5173`.

Без Telegram токена можно просматривать каталог, но нельзя входить, оформлять заказы или открывать админку. Нет тестового входа, универсального пароля или клиентского переключателя ролей.

Для локального просмотра без установленного PostgreSQL:

```bash
npm ci
npm run build
node server/preview.js
```

Этот отдельный процесс использует временный PGlite, теряет данные после остановки, не даёт входа и не используется Docker или Railway.

## Railway — один сервис приложения + PostgreSQL

1. Создайте отдельный проект и добавьте **PostgreSQL из шаблона Railway с постоянным volume**. Не используйте контейнер базы без постоянного диска.
2. Добавьте сервис из репозитория `giwi072103-arch/moyka`, ветка `main`.
3. Railway соберёт `Dockerfile`. Приложение слушает `0.0.0.0:$PORT`, проверка здоровья `/api/health`.
4. В Variables сервиса приложения установите:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Ссылка Railway на `Postgres.DATABASE_URL` через Add Reference (фактическое имя базы может отличаться) |
| `NODE_ENV` | `production` |
| `APP_URL` | Полный HTTPS-домен сервиса, **без завершающего /** |
| `BOT_TOKEN` | Токен своего бота из BotFather |
| `ADMIN_TELEGRAM_IDS` | Ваш числовой Telegram ID; для нескольких владельцев — через запятую |
| `TRUST_PROXY_HOPS` | `1` для одного доверенного reverse proxy |
| `CARD_ENCRYPTION_KEY` | Необязательно: 64 hex-символа (32 случайных байта) |

5. Сгенерируйте домен Railway, внесите его в `APP_URL` и выполните redeploy. Не меняйте `APP_URL` на адрес Telegram.
6. Таблицы и стартовый каталог создаются при запуске в транзакции с advisory lock. Существующие цены и данные не перезаписываются.
7. Проверьте `/api/health`, успешный deploy, затем настройте Mini App в BotFather.
8. В BotFather: `/mybots` → ваш бот → Bot Settings → Configure Mini App / Menu Button → HTTPS URL приложения. Название кнопки: «Открыть автомойку».
9. Откройте приложение через эту кнопку. Пользователь с ID из `ADMIN_TELEGRAM_IDS` получает управление после входа. Проверьте цены и контакты, затем одобрите заявки сотрудников.

У бота не нужен polling-процесс: приложение запускается через Menu Button / Main Mini App. Отдельная обработка `/start` и push-уведомления не включены; статусы и сообщения доступны внутри приложения.

Если включаете чаевые, ключ можно создать локально:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Сохраните ключ в защищённых переменных Railway. Его потеря делает ранее зашифрованные реквизиты недоступными. Не записывайте PIN, срок действия или CVV.

## Безопасность и данные

Telegram HMAC-SHA256 проверяется на сервере; срок initData — 1 час. Сессии хранятся в PostgreSQL в виде SHA-256 хешей, срок — 7 дней. В приложении Telegram токен сессии используется в памяти через Authorization, что позволяет работать без сторонних cookies. Дополнительно устанавливается HttpOnly-cookie. Реальная среда production требует HTTPS.

Все изменения проверяют точный Origin из `APP_URL`. На API действуют ограничения частоты запросов. SQL использует параметры; доступ к заказам, переписке, фотографиям и админке проверяется сервером. Ключи и токены не передаются в сборку frontend.

Переход статуса выполняется в транзакции с блокировкой заказа. Частичные уникальные индексы запрещают одновременно выполнять два заказа одному мойщику или создавать два активных заказа для одной машины. Оплата не следует автоматически из статуса мойки.

Фото находятся в PostgreSQL и доступны только владельцу, администратору и назначенному мойщику во время активного заказа. Требуются резервные копии базы и план хранения персональных данных. Автоматическое удаление старых фото/чатов, восстановление резервных копий и нагрузочное тестирование не включены. Проверьте их под реальные объёмы до широкого запуска. API ограничивает выдачу: 200 заказов и 500 пользователей; для больших объёмов потребуется пагинация.

Не разворачивайте `server/preview.js` в production. Не отключайте проверку Telegram ради тестового входа.

## Проверки

```bash
npm test
npm run build
npm audit --omit=dev
```

Тесты запускают настоящий SQL-движок PostgreSQL в PGlite и проверяют подпись Telegram, неправильные и устаревшие данные входа, права ролей, привязку автомобиля к владельцу, фиксацию цены, жизненный цикл заказа, закрытие чата, отзывы, блокировки, CSRF и журнал. PGlite не заменяет проверку конкурентных запросов на живом PostgreSQL. CI запускает тесты и сборку.

Перед открытием клиентам проверьте с тремя реальными Telegram аккаунтами: клиент → заказ; мойщик → заявка и принятие; владелец → одобрение и оплата. Проверьте внешний вид на iPhone и Android, загрузку фото и работу после перезапуска Railway.

## Структура

- `server/app.js` — API, роли, заказы, чат и администрирование.
- `server/security.js` — Telegram, криптография, номера и статусы.
- `server/schema.sql`, `server/db.js` — PostgreSQL и начальная инициализация.
- `web/src/main.jsx`, `web/src/style.css` — интерфейс.
- `tests/` — проверки безопасности и сценариев.
- `Dockerfile`, `railway.toml`, `.github/workflows/ci.yml` — сборка, развёртывание и CI.
